# Hisobdon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement task-by-task. Execution and deployment were explicitly authorized by the owner.

**Goal:** Ship a single-owner Uzbek Telegram finance bot and deploy it on the existing Netcup host.
**Architecture:** Durable SQLite inbox/drafts, atomic ledger movements, framework-independent conversation engine, aiogram transport, persisted scheduled reports. Snapshot exports and encrypted SQLite backups.
**Tech Stack:** Python 3.12, aiogram 3, SQLite, openpyxl, cryptography, Docker Compose.
**Spec:** ../specs/2026-10-27-hisobdon-design.md

## Global Constraints

- UZS and USD; integer tiyin/cents, never binary floating point for money.
- Owner-only private chat; secrets/owner identifiers/financial records never committed.
- Asia/Tashkent: daily 22:00, weekly Monday 09:00, monthly first day 09:00, debts due 09:00.
- Raw messages and drafts survive restart. Idempotent input and atomic mutations.
- No AI API, bank integration, or public web service.
- New fresh clone on feature branch provides isolation; do not disturb unrelated projects.

## Review Focus

- Duplicate or stale buttons must not reapply/revert someone else's operation (tasks 1, 2).
- Uzbek amount/date variants, multiple numbers and ambiguous input must not silently charge wrong amounts (task 2).
- Corrections of already-repaid debts and backdated events must preserve nonnegative principal (task 1).
- Late cross-month messages and history edits must preserve raw export completeness and as-of balances (task 3).
- Interrupted backup/upload or report delivery must leave recoverable state and explicit retries (tasks 3, 4).
